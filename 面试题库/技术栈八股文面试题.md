# 一、Java 基础（本项目用到的部分）

---

### 1.1 ⭐⭐⭐ 面向对象三大特征是什么？

**八股文答案：**
封装、继承、多态。

**封装：** 把数据和操作数据的方法绑定在一起，对外隐藏内部实现细节。通过 `private` 关键字隐藏属性，通过 `public` 方法暴露接口。

**继承：** 子类可以继承父类的属性和方法。用 `extends` 关键字。子类可以扩展自己的新功能，也可以重写父类的方法。Java 是单继承（一个子类只能有一个父类）。

**多态：** 同一个方法在不同对象中有不同的实现。父类引用指向子类对象，调用方法时执行的是子类的方法。通过方法重写（Override）实现。

**大白话：**
- 封装：把东西装进黑盒子，外面只能按按钮，看不到里面的电路
- 继承：儿子继承老爸的财产，还能自己赚更多
- 多态：都是"动物"，但猫叫"喵"，狗叫"汪"

### 1.2 ⭐⭐⭐ 重载（Overload）和重写（Override）的区别？

| 对比 | 重载（Overload） | 重写（Override） |
|------|-----------------|-----------------|
| 发生位置 | 同一个类中 | 父子类之间 |
| 方法名 | 必须相同 | 必须相同 |
| 参数列表 | 必须不同 | 必须相同 |
| 返回值 | 可以不同 | 必须相同 |
| 关键字 | 无 | `@Override` |
| 目的 | 提供多个同名方法 | 父类方法不满足需求时重写 |

**大白话：** 重载=同一个名字但参数不同（比如 `add(int a)` 和 `add(int a, int b)`）。重写=儿子觉得老爸的方法不好用，自己重新写一个。

### 1.3 ⭐⭐ 接口（Interface）和抽象类（Abstract Class）的区别？

| 对比 | 接口 | 抽象类 |
|------|------|--------|
| 关键字 | `interface` | `abstract class` |
| 方法体 | 默认没有方法体（Java 8 后可以有 default 方法） | 可以有抽象方法和普通方法 |
| 构造方法 | 不能有 | 可以有 |
| 多继承 | 一个类可以实现多个接口 | 一个类只能继承一个抽象类 |
| 成员变量 | 只能是 `public static final` 常量 | 可以是普通成员变量 |

**大白话：** 接口=你承诺会做某事（签合同），抽象类=事情做到一半交给你做（半成品）。

本项目用法：`public interface UserService { ... }` + `public class UserServiceImpl implements UserService`

### 1.4 ⭐⭐⭐ final 关键字的作用？

**八股文答案：**
- `final` 修饰**类**：该类不能被继承（如 `String` 类）
- `final` 修饰**方法**：该方法不能被重写
- `final` 修饰**变量**：该变量变成常量，值不能被修改

**大白话：** final 就是"到此为止"——类不能有子类，方法不能重写，变量不能改值。

---

### 1.5 ⭐⭐ static 关键字的作用？

**八股文答案：**
- `static` 修饰**变量**：类变量，所有对象共享同一份
- `static` 修饰**方法**：类方法，不用创建对象就能调用（如 `Math.random()`）
- `static` 修饰**代码块**：类加载时执行一次

**大白话：** static = 全局共有。不用new就能用，所有对象共享。

### 1.6 ⭐⭐⭐ String、StringBuilder、StringBuffer 的区别？

| | String | StringBuilder | StringBuffer |
|--|--------|--------------|-------------|
| 可变性 | 不可变 | 可变 | 可变 |
| 线程安全 | 安全（不可变） | 不安全 | 安全（synchronized） |
| 性能 | 拼接字符串时最差 | 最好 | 较好 |
| 使用场景 | 少量字符串操作 | 单线程大量拼接 | 多线程大量拼接 |

**大白话：** String 是"一次写好不能改"，拼接字符串时会不断创建新对象。StringBuilder 是"可以随便改"，最快但不是线程安全。StringBuffer 是"安全的 StringBuilder"，慢一点但放心。

### 1.7 ⭐⭐ ArrayList 和 LinkedList 的区别？

| 对比 | ArrayList | LinkedList |
|------|-----------|------------|
| 底层结构 | 动态数组 | 双向链表 |
| 查询效率 | 快（O(1)通过下标） | 慢（O(n)需要遍历） |
| 插入删除 | 慢（需要移动元素） | 快（修改指针） |
| 内存占用 | 连续内存 | 每个节点多存前后指针 |

**大白话：** ArrayList=一排连座的电影院，找座位快但中间插人费劲。LinkedList=手拉手的人链，中间插人容易但找人要一个个问。

### 1.8 ⭐⭐ HashMap 的底层原理？

**八股文答案：**
HashMap 底层是**数组+链表+红黑树**（JDK 8+）。数组用来存数据，链表用来解决哈希冲突。
1. 调用 `put(key, value)` 时，先对 key 计算 hashCode，再通过哈希函数算出数组下标
2. 如果该位置为空，直接存入
3. 如果该位置有数据（哈希冲突），用 equals 比较 key。相同就覆盖，不同就挂到链表上
4. 当链表长度 >= 8 时，链表转成红黑树（提高查询效率）
5. 当元素数量超过负载因子（0.75）× 容量时，扩容为原来的2倍

**大白话：** 想象一排桶（数组），我要存一个东西，先算 hashcode 决定放哪个桶。桶里已经有东西了，就挂在后面形成链。链太长就改成树结构，查找更快。

### 1.9 ⭐⭐ equals() 和 == 的区别？

**八股文答案：**
- `==` 比较的是**内存地址**（引用是否指向同一个对象），基本类型比较值
- `equals()` 比较的是**内容**（默认也是比较地址，但 String、Integer 等类重写了，变成比较值）

**大白话：** `==` 问的是"你们俩是不是同一个人？" `equals()` 问的是"你们俩是不是一样高？"

### 1.10 ⭐ try-catch-finally 的执行顺序？

**八股文答案：**
1. 先执行 try 块中的代码
2. 如果没有异常：跳过 catch，执行 finally。finally 执行完，再执行 try 块后面的代码
3. 如果有异常：跳到对应的 catch 块，catch 执行完，执行 finally
4. 即使 try 或 catch 中有 return 语句，finally 也会在 return 之前执行

**特殊注意：** 如果 finally 中也有 return，会覆盖 try/catch 中的 return。不要在 finally 里写 return！

**大白话：** try=你试试，catch=出错了怎么办，finally=不管出不出错都要做。

### 1.11 ⭐ Java 的基本数据类型有哪些？

**八股文答案：**
8种基本数据类型：
- **整数型**：byte（1字节）、short（2字节）、int（4字节）、long（8字节）
- **浮点型**：float（4字节）、double（8字节）
- **字符型**：char（2字节）
- **布尔型**：boolean（1位）

**大白话：** 整数4种（byte/short/int/long），小数2种（float/double），字符1种（char），真假1种（boolean）。

### 1.12 ⭐⭐ 什么是自动装箱和拆箱？

**八股文答案：**
- 自动装箱：基本类型自动转成包装类。如 `Integer i = 100;`（int → Integer）
- 自动拆箱：包装类自动转成基本类型。如 `int j = i;`（Integer → int）

包装类：Integer、Long、Double、Boolean、Character 等（8大基本类型对应8个包装类）。

**大白话：** 装箱=把零件装进盒子（基本类型→对象），拆箱=从盒子里拿出零件（对象→基本类型）。Java 5+ 自动帮你做，不用手动转换。

# 二、MySQL 数据库

### 2.1 ⭐⭐⭐ 什么是 SQL？SQL 分为哪几类？

**八股文答案：**
SQL（Structured Query Language）是结构化查询语言，用来操作数据库。

分为4类：
| 分类 | 英文 | 作用 | 关键字 |
|------|------|------|--------|
| DDL | Data Definition Language | 定义数据库结构 | CREATE, ALTER, DROP |
| DML | Data Manipulation Language | 操作数据 | INSERT, UPDATE, DELETE |
| DQL | Data Query Language | 查询数据 | SELECT |
| DCL | Data Control Language | 控制权限 | GRANT, REVOKE |

**大白话：** DDL=建表删表，DML=增删改，DQL=查，DCL=给权限。面试最常考的是 DML 和 DQL。

---

### 2.2 ⭐⭐⭐ 说说 LEFT JOIN、INNER JOIN、RIGHT JOIN 的区别？

**八股文答案：**
假设有 A 表和 B 表：

- **INNER JOIN（内连接）：** 返回 A ∩ B，两表中都有匹配的数据
- **LEFT JOIN（左连接）：** 返回 A 全部 + B 中匹配的数据，A 有 B 没有的字段填 NULL
- **RIGHT JOIN（右连接）：** 返回 B 全部 + A 中匹配的数据，B 有 A 没有的字段填 NULL

**大白话：**
- INNER JOIN：交集
- LEFT JOIN：左表全要，右表有的拿过来，没有的填NULL
- RIGHT JOIN：右表全要，左表有的拿过来，没有的填NULL

**本项目用法：** 多表关联查询用户和部门时用 LEFT JOIN。

---

### 2.3 ⭐⭐⭐ 什么是索引？有什么用？

**八股文答案：**
索引是一种**数据结构**（B+树），用来提高数据库查询速度。类似于书的目录。

**优点：**
- 提高查询速度（主要目的）
- 加速排序和分组操作

**缺点：**
- 占用额外存储空间
- 增删改数据时需要维护索引（变慢）

**大白话：** 没有索引=一本没有目录的字典，要找一个字必须从头翻到尾。有索引=有目录，直接翻到指定页。

---

### 2.4 ⭐⭐⭐ 什么是主键？什么是外键？

**八股文答案：**
- **主键（Primary Key）：** 唯一标识表中每一条记录的字段。不能为 NULL，必须唯一。一张表只能有一个主键
- **外键（Foreign Key）：** 指向另一张表的主键。用来保证数据完整性和表之间的关联

**大白话：**
- 主键=身份证号，每个人都不一样，且不能为空
- 外键=你说你在"研发部"，这个部门必须在部门表里存在

---

### 2.5 ⭐⭐ 什么是事务？ACID 是什么？

**八股文答案：**
事务是一组数据库操作，要么全部成功，要么全部失败。

**ACID 四大特性：**
| 特性 | 含义 | 大白话 |
|------|------|--------|
| A（原子性） | 事务不可分割，要么全做要么全不做 | 钱要么转出去，要么没转，不存在转了又被扣了 |
| C（一致性） | 事务前后数据保持一致 | 总金额不变，转出200，对方就+200 |
| I（隔离性） | 并发事务互不干扰 | 你转钱时别人查余额，看到的是一致的 |
| D（持久性） | 事务提交后数据永久保存 | 只要你确认转钱了，数据库宕机了也不会丢 |

**本项目用法：** 启动类加了 `@EnableTransactionManagement`，涉及多个表操作时用 `@Transactional` 保证事务。

---

### 2.6 ⭐⭐ 什么是 SQL 注入？怎么防？

**八股文答案：**
SQL 注入就是攻击者在输入框中写 SQL 代码，让数据库执行恶意操作。

**举例（错误写法）：**
```java
// 直接拼接 SQL：
String sql = "SELECT * FROM user WHERE name = '" + input + "'";
// 如果输入 ' OR 1=1 --  就变成了：
// SELECT * FROM user WHERE name = '' OR 1=1 --'  查出了全部用户！
```

**防止方法：**
1. **预编译 + 参数绑定（推荐）：** MyBatis 用 `#{}` 而不是 `${}`
2. 对用户输入做过滤和校验
3. 最小化数据库权限

**本项目用法：** MyBatis-Plus 默认用 `#{}` 预编译，天然防 SQL 注入。

### 2.7 ⭐⭐ varchar 和 char 的区别？

| | varchar | char |
|--|---------|------|
| 长度 | 可变长度 | 固定长度 |
| 存储 | 存多少占多少 + 1-2字节记录长度 | 不管存多少都占满 |
| 性能 | 略慢（需要计算长度） | 更快 |
| 使用场景 | 姓名、地址等变长数据 | 手机号、身份证等固定长度数据 |

**大白话：** varchar=根据内容大小自动调整（存3个字占3个字空间），char=固定占位置（说好10个字的位子，存3个字也占10个字）。

### 2.8 ⭐ 什么是数据库的三大范式？

**八股文答案：**
1. **第一范式（1NF）：** 每列不可拆分。比如"地址"不能包含"省市区"，要拆成三列
2. **第二范式（2NF）：** 在1NF基础上，每列都完全依赖于主键。不能主键是A+B，但某列只依赖A
3. **第三范式（3NF）：** 在2NF基础上，非主键列不能依赖于其他非主键列（不能有传递依赖）

**大白话：**
- 1NF：列不能再分（地址拆成省、市、区）
- 2NF：每个字段都和主键相关（订单表不能出现"用户名"，因为用户名只和"用户ID"相关，不是和"订单ID"相关）
- 3NF：字段之间不能有依赖关系（学生表里有"系主任"，但系主任依赖于"系"，应该放到系表里）

### 2.9 ⭐⭐ EXISTS 和 IN 的区别？

**八股文答案：**
```sql
-- IN：子查询先执行，把结果集返回给外层
SELECT * FROM user WHERE dept_id IN (SELECT id FROM dept WHERE status = 1);

-- EXISTS：外层循环每条记录，用记录去子查询里判断是否存在
SELECT * FROM user WHERE EXISTS (SELECT 1 FROM dept WHERE dept.id = user.dept_id AND status = 1);
```

区别：
- **IN** 子查询先执行，适合子查询结果集小的情况
- **EXISTS** 外层先遍历，适合外层结果集小、内层表大的情况
- EXISTS 找到匹配值就停止（提前终止），IN 要把子查询全部查完

### 2.10 ⭐⭐ 分页查询怎么写？

**MySQL 写法（本项目用的是这个）：**
```sql
-- MySQL：LIMIT (当前页-1) * 每页条数, 每页条数
SELECT * FROM user LIMIT 0, 10;    -- 第1页，每页10条
SELECT * FROM user LIMIT 10, 10;   -- 第2页，每页10条
SELECT * FROM user LIMIT 20, 10;   -- 第3页，每页10条
```

**本项目用法：** MyBatis-Plus 直接封装了分页，不用手写 SQL：
```java
Page<User> page = new Page<>(1, 10);
Page<User> result = userMapper.selectPage(page, wrapper);
```

# 三、Spring Boot

### 3.1 ⭐⭐⭐ Spring Boot 和 Spring 的区别？

**八股文答案：**
Spring 是一个轻量级 Java 开发框架，提供了 IOC（控制反转）和 AOP（面向切面编程）等核心功能。但 Spring 的配置非常繁琐（需要写大量的 XML 配置文件）。

Spring Boot 在 Spring 基础上做了**自动配置**和**起步依赖**两大改进：
1. **自动配置**：根据 classpath 中的依赖自动配置 Spring 应用。比如你在 pom.xml 加了 `spring-boot-starter-web`，它自动配置好 Tomcat 和 Spring MVC
2. **起步依赖**：把相关依赖打包在一起，一个 starter 依赖等于一堆相关依赖。比如加了 `mybatis-plus-boot-starter`，自动引入 MyBatis、连接池等
3. **内嵌容器**：内嵌 Tomcat/Jetty，不需要单独部署 WAR 包
4. **actuator**：提供监控和管理的端点

**大白话：** Spring 是毛坯房，你要自己装修（配 XML）。Spring Boot 是精装房，拎包入住（自动配置）。

---

### 3.2 ⭐⭐⭐ @SpringBootApplication 注解包含哪些注解？

**八股文答案：**
它是组合注解，主要由3个注解组成：
1. **@SpringBootConfiguration：** 标记这是一个配置类（底层是 @Configuration）
2. **@EnableAutoConfiguration：** 开启自动配置（从 spring.factories 加载配置类）
3. **@ComponentScan：** 自动扫描当前包及子包下的 @Component、@Service、@Controller、@Repository 等注解

**大白话：** 三个功能合一：① 这是配置类 ② 自动配好各种组件 ③ 自动找到并注册所有 Bean。

---

### 3.3 ⭐⭐⭐ IOC（控制反转）是什么？

**八股文答案：**
IOC（Inversion of Control，控制反转）是一种设计原则：**对象的创建和管理权交给 Spring 容器**，程序员不再自己 new 对象。

传统方式：
```java
UserService userService = new UserServiceImpl();  // 自己创建
```

Spring 方式：
```java
@Autowired
private UserService userService;  // Spring 自动注入
```

**优点：**
- 解耦：类和类之间不直接依赖，通过容器管理
- 方便：不用手动管理对象的生命周期
- 易于测试：可以方便的替换 mock 对象

**大白话：** 原来你自己找房子（new 对象），现在告诉中介（Spring 容器）你要什么，中介帮你找好送过来（依赖注入）。

---

### 3.4 ⭐⭐⭐ 依赖注入（DI）有哪几种方式？

**八股文答案：**
三种注入方式：
1. **字段注入（最常用，本项目用这个）：**
```java
@Autowired
private UserService userService;
```

2. **Setter 注入：**
```java
@Autowired
public void setUserService(UserService userService) {
    this.userService = userService;
}
```

3. **构造器注入（官方推荐）：**
```java
private final UserService userService;

public UserController(UserService userService) {
    this.userService = userService;
}
```

**注意：** 构造器注入是 Spring 官方推荐的方式，因为可以确保依赖不可变（final）且不为 null。字段注入最简单但不利于测试。

---

### 3.5 ⭐⭐ AOP（面向切面编程）是什么？

**八股文答案：**
AOP（Aspect Oriented Programming）是一种编程思想：**把横切关注点（日志、事务、权限等）从业务代码中抽离出来**。

场景举例：
- 每个方法都要记录日志 → 不用在每个方法里写日志代码，用 AOP 统一处理
- 每个方法都需要事务 → 用 `@Transactional` 注解

**核心概念：**
| 术语 | 含义 |
|------|------|
| Aspect（切面） | 横切关注点的模块化（如日志模块） |
| JoinPoint（连接点） | 程序执行中的某个点（如方法调用） |
| Advice（通知） | 切面在连接点执行的动作（before/after/around） |
| Pointcut（切入点） | 匹配连接点的表达式（哪些方法需要增强） |

**本项目用法：** Spring Security 的 `@PreAuthorize` 注解就是基于 AOP 实现的权限控制。

---

### 3.6 ⭐⭐ Bean 的生命周期？

**八股文答案：**
Spring 容器中 Bean 的完整生命周期：
1. **实例化**：通过反射创建 Bean 对象
2. **属性赋值**：给 Bean 的属性注入值（依赖注入）
3. **初始化前**：执行 `@PostConstruct` 或实现 `InitializingBean` 接口
4. **初始化**：执行 `init-method` 指定的方法
5. **初始化后**：AOP 增强（如果有代理）
6. **使用**：Bean 准备就绪，可以被调用
7. **销毁前**：执行 `@PreDestroy` 或实现 `DisposableBean` 接口
8. **销毁**：容器关闭时销毁 Bean

**大白话：** 出生→领身份证（属性赋值）→培训（初始化）→上岗工作→退休前写总结→注销。

### 3.7 ⭐⭐⭐ @Autowired 和 @Resource 的区别？

| 对比 | @Autowired | @Resource |
|------|-----------|-----------|
| 来源 | Spring 框架提供 | Java 提供（javax.annotation） |
| 注入策略 | 先按类型（byType） | 先按名称（byName），再按类型 |

| 多个实现类 | 需要配合 @Qualifier 指定 | 指定 name 属性 |

**大白话：** @Autowired 是"找同类型的"，有多个同类型需要 @Qualifier 指定名字。@Resource 是"找同名字的"，找不到再按类型找。

### 3.8 ⭐⭐ Spring Boot 的自动配置原理是什么？

**八股文答案：**

2. `spring.factories` 文件中列出了所有自动配置类（如 `RedisAutoConfiguration`、`DataSourceAutoConfiguration`）

4. 满足条件时，自动配置类生效，创建对应的 Bean 并注入容器

**大白话：** Spring Boot 启动时，翻看一份"候选人名单"（spring.factories），逐个检查"这个人在吗？"（条件判断），符合条件的自动注册成 Bean。

### 4.1 ⭐⭐⭐ MyBatis-Plus 和 MyBatis 的区别？

**八股文答案：**
| 对比 | MyBatis | MyBatis-Plus |
|------|---------|-------------|
| SQL 编写 | 需要写 XML 映射文件 | 大部分 SQL 自动生成 |

### 4.2 ⭐⭐⭐ #{} 和 ${} 的区别？

**八股文答案：**
| | #{} | ${} |
|--|-----|-----|
| 处理方式 | 预编译，参数占位符 `?` | 直接拼接字符串 |
| SQL 注入 | **防止** SQL 注入 | **不防** SQL 注入 |
| 场景 | 传值 | 传表名、列名等 SQL 关键字 |
| 安全 | 安全 | 不安全 |

```xml
<!-- 安全：MyBatis 会转成 PreparedStatement 的 ? 占位符 -->
SELECT * FROM user WHERE name = #{name}

<!-- 危险：直接拼接，存在 SQL 注入风险 -->
SELECT * FROM ${tableName}
```

**本项目用法：** 99% 用 `#{}`，只有极少数情况（如动态表名）才用 `${}`。

### 4.4 ⭐⭐⭐ QueryWrapper 常用方法有哪些？

### 4.6 ⭐⭐ 什么是逻辑删除？MyBatis-Plus 怎么支持？

**八股文答案：**
逻辑删除不是真的删除数据，而是给数据加一个标记（如 `deleted` 字段），查询时自动过滤掉标记为"已删除"的数据。好处是可以恢复数据，保留历史记录。

MyBatis-Plus 支持方式：
```java
// 1. 实体类字段上加 @TableLogic
@TableLogic
private Integer deleted;  // 0-未删除，1-已删除

// 2. application.yml 配置
mybatis-plus:
  global-config:
    db-config:
      logic-delete-field: deleted    # 全局逻辑删除字段
      logic-delete-value: 1          # 已删除的值
      logic-not-delete-value: 0      # 未删除的值

// 3. 使用：deleteById 变成 update 操作（设置 deleted=1）
// 4. 查询时自动拼接 WHERE deleted=0
```

# 五、Spring Security + JWT

---

### 5.1 ⭐⭐⭐ Spring Security 的工作原理？

**八股文答案：**
Spring Security 基于**过滤器链**实现：
1. 客户端发起请求
2. 请求经过一系列过滤器（Filter Chain）
3. **UsernamePasswordAuthenticationFilter**：处理登录请求（用户名密码认证）
4. **SecurityContextHolder**：存储当前登录用户信息
5. **AccessDecisionManager**：判断是否有权限访问资源
6. **AuthenticationEntryPoint**：未登录时的处理（返回 401）
7. **AccessDeniedHandler**：无权限时的处理（返回 403）

**本项目过滤器链：**
```
请求 → CorsFilter（跨域）→ JwtAuthenticationFilter（JWT认证）→ ... → Controller
```

---

### 5.2 ⭐⭐⭐ JWT 由哪几部分组成？

**八股文答案：**
JWT 由三部分组成，用 `.` 分隔：
```
header.payload.signature
```

1. **Header（头部）：** 声明类型和加密算法
```json
{"alg": "HS256", "typ": "JWT"}
```

2. **Payload（载荷）：** 携带的数据（如用户ID、过期时间）
```json
{
  "sub": "admin",
  "userId": "1",
  "iat": 1700000000,
  "exp": 1700604800
}
```
标准字段：
- `sub`（主题，一般是用户ID）
- `iat`（签发时间）
- `exp`（过期时间）
- `iss`（签发者）

3. **Signature（签名）：** 对前两部分用密钥加密，防止篡改
```
HMACSHA256(base64UrlEncode(header) + "." + base64UrlEncode(payload), secret)
```

**大白话：** 第一部分说"我用HS256算法加密"，第二部分存"用户id=1，7天后过期"，第三部分是防伪签名。

---

### 5.3 ⭐⭐⭐ JWT 认证的完整流程？

**八股文答案：**
```
【登录】
前端 → POST /login（用户名+密码）→ 后端验证 → 生成JWT → 返回令牌

【请求】
前端 → GET /api/data（Header: Authorization: Bearer xxx）
    → JwtAuthenticationFilter 拦截
    → 从 Header 取出 token
    → 解析 token 验证签名和过期时间
    → 从 token 中提取用户信息
    → 放入 SecurityContextHolder
    → 放行到 Controller

【未登录】
请求没有 token 或 token 过期 → 返回 401

【无权限】
有 token 但角色权限不够 → 返回 403
```

---

### 5.4 ⭐⭐ JWT 和 Session 的区别？

| 对比 | JWT | Session |
|------|-----|---------|
| 存储位置 | 客户端（浏览器） | 服务器内存 |
| 状态 | 无状态 | 有状态 |
| 扩展性 | 好（任何服务器都能验证） | 差（需要共享Session或粘性Session） |
| 注销 | 难（JWT过期前一直有效） | 容易（删除Session即可） |
| 安全 | base64编码，payload明文（含敏感信息需加密） | Session ID 通常较短且随机 |
| 跨域 | 支持好 | 需要额外配置 |

**大白话：** JWT = 你戴着手环进游乐园，工作人员看一眼就知道你能玩什么。Session = 你办张会员卡，每次去都要先查一下电脑记录。

---

### 5.5 ⭐⭐ JWT 怎么防止被篡改？

**八股文答案：**
JWT 的第三部分（Signature）是用密钥对 header 和 payload 进行签名生成的。如果有人修改了 payload，接收方重新计算签名时，新的签名和原来的签名不匹配，验证就失败了。密钥只在服务端保存，客户端不知道密钥，无法生成有效的签名。

**注意：** JWT 的 payload 只是 base64 编码（不是加密），任何人都可以解码看到内容。所以**不要在 JWT 中存储密码等敏感信息**。

---

### 5.6 ⭐⭐ BCryptPasswordEncoder 是什么？

**八股文答案：**
BCryptPasswordEncoder 是 Spring Security 提供的密码加密器，使用 BCrypt 加密算法。

特点：
1. **加盐**：每次加密结果都不同（自动加入随机盐）
2. **慢哈希**：故意设计得慢，增加暴力破解成本
3. **自包含**：加密结果中包含了盐值，验证时自动提取

```java
// 加密（每次结果都不一样）
String encoded = encoder.encode("123456");
// 结果示例：$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy

// 验证
boolean match = encoder.matches("123456", encodedPassword);  // true
```

### 5.7 ⭐⭐ @PreAuthorize 注解怎么用？

**八股文答案：**
`@PreAuthorize` 是 Spring Security 的**方法级别权限控制**注解。在方法执行前检查用户是否有权限：

```java
// 登录用户可以访问
@PreAuthorize("isAuthenticated()")

// 具有 admin 角色的用户可以访问
@PreAuthorize("hasRole('admin')")

// 具有 user:list 权限的用户可以访问
@PreAuthorize("hasAuthority('user:list')")

// 自定义校验（SpEL 表达式）
@PreAuthorize("#userId == authentication.principal.id")
```

需要在配置类上用 `@EnableGlobalMethodSecurity(prePostEnabled = true)` 开启（本项目已配置）。

# 六、Redis

---

### 6.1 ⭐⭐⭐ Redis 是什么？有哪些数据类型？

**八股文答案：**
Redis 是一个**基于内存的键值对数据库**，性能极高（读写10万+/秒）。常用于缓存、分布式锁、计数器等场景。

**五种基本数据类型：**
| 类型 | 说明 | 示例 |
|------|------|------|
| String（字符串） | 最常用 | `set key value` |
| Hash（哈希） | 存储对象 | `hset user:1 name "张三" age 25` |
| List（列表） | 有序列表 | `lpush list a b c` |
| Set（集合） | 无序不重复 | `sadd set a b c` |
| Zset（有序集合） | 带权重的集合 | `zadd rank 100 "张三"` |

**本项目用到的：** 主要是 String 和 Hash，通过 RedisUtil 操作。

---

### 6.2 ⭐⭐⭐ Redis 为什么这么快？

**八股文答案：**
1. **基于内存**：数据存在内存中，读写速度比硬盘快几个数量级
2. **单线程模型**：避免了锁竞争和上下文切换的开销，所有命令串行执行
3. **I/O 多路复用**：用 epoll 同时处理多个连接，而不是每个连接一个线程
4. **高效的数据结构**：底层用压缩表、跳跃表等优化过的数据结构

**注意：** Redis 6.0+ 在网络处理层引入了多线程，但命令执行仍然是单线程。

---

### 6.3 ⭐⭐⭐ Redis 的过期策略？

**八股文答案：**
Redis 有三种过期删除策略：
1. **定时删除**：设置过期时间时创建一个定时器（CPU 不友好，不常用）
2. **惰性删除**：访问 key 时检查是否过期，过期才删除（内存不友好）
3. **定期删除**：每隔100ms随机抽取一批 key，检查并删除过期 key（折中方案）

**Redis 实际使用：定期删除 + 惰性删除 两种策略结合。**

---

### 6.4 ⭐⭐ Redis 缓存穿透、缓存击穿、缓存雪崩？

**八股文答案：**

| 问题 | 现象 | 解决方案 |
|------|------|---------|
| **缓存穿透** | 查询一个**不存在的数据**，缓存没有，数据库也没有。每次请求都直接打到数据库 | ① 缓存空值（设置短过期时间）② 布隆过滤器 |
| **缓存击穿** | **某个热点 key 过期**，大量并发请求同时打到数据库 | ① 互斥锁 ② 热点 key 永不过期 |
| **缓存雪崩** | **大量 key 同时过期**，大量请求涌入数据库 | ① 过期时间加随机值 ② 集群部署 ③ 多级缓存 |

**大白话：**
- 穿透：查不存在的ID，每次都穿透Redis打到MySQL
- 击穿：一个热门链接（比如双11商品）的缓存刚好过期，大家一窝蜂地查数据库
- 雪崩：双11零点，所有商品的缓存一起过期，所有人同时查数据库

---

### 6.5 ⭐⭐ 你怎么保证 Redis 和数据库的数据一致性？

**八股文答案：**
几种常见策略：

1. **先更新数据库，再删除缓存**（推荐做法）：
```java
// 1. 更新数据库
userMapper.updateById(user);
// 2. 删除缓存（下次查询时重新加载）
redisUtil.del("user:" + user.getId());
```

2. **延迟双删**：
```java
// 1. 删除缓存
redisUtil.del("user:" + id);
// 2. 更新数据库
userMapper.updateById(user);
// 3. 延迟500ms再删除一次
Thread.sleep(500);
redisUtil.del("user:" + id);
```

3. **设置过期时间兜底**：即使不一致，过期后也会自动恢复

**本项目用法：** 本项目缓存的是不常变化的数据，设置了过期时间，不需要强一致性。

### 6.6 ⭐⭐ 什么是 Redis 的持久化？

**八股文答案：**
Redis 是内存数据库，断电会丢数据。持久化就是把内存中的数据存到硬盘上。

两种方式：
| 方式 | 原理 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|---------|
| **RDB（快照）** | 定期把内存全量数据 dump 到文件 | 文件小、恢复快、性能影响小 | 可能丢数据 | 缓存场景 |
| **AOF（追加文件）** | 记录每条写命令，追加到文件 | 数据更完整 | 文件大、恢复慢 | 数据安全要求高的场景 |

**本项目：** 默认配置，一般是 RDB 方式。

### 7.2 ⭐⭐⭐ Vue 的 v-if 和 v-show 区别？

| 对比 | v-if | v-show |
|------|------|--------|
| 渲染方式 | 条件为 false 时不渲染 DOM | 始终渲染，通过 display:none 隐藏 |
| 切换开销 | 每次都要创建/销毁 DOM 节点 | 只切换 display 属性 |
| 初始渲染 | 条件为 false 时不渲染 | 不管显不显示都渲染 |
| 使用场景 | 切换频率低的场景 | 切换频率高的场景 |

**速记口诀：** `v-if` = 真才渲染，假就销毁（适合不频繁切换的）；`v-show` = 一直渲染，只是藏起来（适合频繁切换的）。

### 7.4 ⭐⭐⭐ Vue 的 computed 和 watch 区别？

| 对比 | computed（计算属性） | watch（监听器） |
|------|-------------------|----------------|
| 功能 | 根据已有数据计算新值 | 监听数据变化执行操作 |
| 缓存 | 有缓存（依赖不变就不重新计算） | 无缓存 |
| 异步 | 不支持异步 | 支持异步 |
| 使用场景 | 简单的数据转换、格式化 | 数据变化后需要执行复杂操作 |

**大白话：** computed = 计算并缓存结果，适合"从现有数据算出新数据"。watch = 监听到变化就干活，适合"变化后发请求"。

```javascript
// computed：计算属性
computed: {
    fullName() {
        return this.firstName + this.lastName;  // 依赖不变就不重新计算
    }
}

// watch：监听器
watch: {
    searchText(newVal) {
        // 搜索框内容变了，调用后端接口搜索
        this.search(newVal);
    }
}
```

### 7.5 ⭐⭐ Vue 的 key 属性有什么用？

**八股文答案：**
`key` 是 Vue 在更新虚拟 DOM 时识别节点的**唯一标识**。

**作用：**
1. 帮助 Vue 复用和重新排序 DOM 元素（提高性能）
2. 在 `v-for` 循环中，让 Vue 追踪每个节点的身份

**最佳实践：**
```html
<!-- 用唯一 ID，不要用 index -->
<tr v-for="(item, index) in list" :key="item.id">
  <!-- key=item.id，每个节点有唯一标识 -->
  <!-- 如果 key=index，新增/删除/排序时可能出问题 -->
</tr>
```

**为什么不能用 index？** 如果列表顺序变了（排序、删除非最后一项），index 对应的数据改变了，但 Vue 认为"index=0 还是那个节点"，导致页面显示错乱。

### 7.6 ⭐⭐ Vue 的 MVVM 是什么？

**八股文答案：**
MVVM 是一种设计模式，由三部分组成：
| 部分 | 含义 | 类比 |
|------|------|------|
| **M（Model）** | 数据层（data） | 脑子里的数据 |
| **V（View）** | 视图层（template） | 写在黑板上的内容 |
| **VM（ViewModel）** | 连接层（Vue实例） | 手，根据脑子里的数据写黑板 |

**Vue 的 MVVM 工作流程：**
1. ViewModel 监听 View 的变化（用户在输入框打字）→ 自动更新 Model
2. ViewModel 监听 Model 的变化（数据变了）→ 自动更新 View

**核心：** 开发者只需要操作数据（Model），Vue 自动帮你更新页面（View）。

### 7.7 ⭐⭐ Vue Router 的两种模式？

**八股文答案：**
| 模式 | 实现方式 | URL 示例 | 服务端配置 |
|------|---------|---------|-----------|
| hash 模式 | URL 的 `#` 号后面部分变化不会发请求 | `http://localhost/#/home` | 不需要 |
| history 模式 | 利用 HTML5 History API | `http://localhost/home` | 需要配置 Nginx 统一指向 index.html |

**历史模式问题：** 如果用户直接在浏览器输入 `http://localhost/home`，会把请求发到后端。后端没有 `/home` 这个接口，返回 404。解决方案是 Nginx 配置：如果找不到文件，就返回 index.html。

**本项目用法：** 用 history 模式（更美观）。

### 7.8 ⭐⭐⭐ 什么是路由守卫（导航守卫）？

**八股文答案：**
路由守卫是在**跳转到某个路由之前或之后执行的函数**，用来做权限校验、登录判断等。

**三种守卫：**
```javascript

    if (to.path !== '/login' && !token) {
        next('/login');  // 未登录，跳转到登录页
    } else {
        next();  // 已登录，放行
    }
});

// 2. 路由独享守卫
{
    path: '/admin',
    component: Admin,
    beforeEnter: (to, from, next) => { /* ... */ }
}

// 3. 组件内守卫
beforeRouteEnter(to, from, next) { /* ... */ }
```

### 7.9 ⭐⭐ $nextTick 是干什么的？

**八股文答案：**
`$nextTick` 在 DOM 更新完成后执行回调函数。因为 Vue 的数据更新是异步的（做了批处理优化），修改数据后 DOM 不会立即更新。

```javascript
this.name = '张三';         // 1. 修改数据
console.log(this.$el.textContent);  // 2. 还是旧值！
this.$nextTick(() => {
    console.log(this.$el.textContent);  // 3. 现在是 "张三"
});
```

**使用场景：** 修改数据后需要操作 DOM（比如更新后获取元素高度、初始化图表）。

### 9.1 ⭐⭐⭐ Axios 是什么？怎么用？

**八股文答案：**
Axios 是一个**基于 Promise 的 HTTP 客户端**，用来在浏览器中发送 Ajax 请求。常用于前端调用后端接口。

### 9.2 ⭐⭐ Promise 是什么？

**八股文答案：**
Promise 是 JavaScript 中**处理异步操作**的对象。代表一个未来才会完成的操作。

**三种状态：**
- **Pending（等待中）**：初始状态
- **Fulfilled（已成功）**：操作成功
- **Rejected（已失败）**：操作失败

状态只能从 Pending → Fulfilled 或 Pending → Rejected，**不可逆**。

```javascript
// 传统回调（回调地狱）
axios.get('/api/user', res => {
    axios.get('/api/dept', res2 => {
        axios.get('/api/role', res3 => {
            // 越来越深
        });
    });
});

// Promise 链式调用
axios.get('/api/user')
    .then(res => axios.get('/api/dept'))
    .then(res => axios.get('/api/role'))
    .catch(err => console.error(err));

// async/await（最优雅，本项目用这个）
async function loadData() {
    try {
        const userRes = await axios.get('/api/user');
        const deptRes = await axios.get('/api/dept');
        // 像写同步代码一样写异步
    } catch (err) {
        console.error(err);
    }
}
```

### 9.3 ⭐⭐⭐ Axios 拦截器怎么用？

**八股文答案：**
```javascript
// 请求拦截器：每次请求前执行
axios.interceptors.request.use(config => {
    // 在请求头中加 token
    const token = localStorage.getItem('token');
    if (token) {
        config.headers['Authorization'] = 'Bearer ' + token;
    }
    return config;  // 必须 return
}, error => {
    return Promise.reject(error);
});

// 响应拦截器：收到响应后执行
axios.interceptors.response.use(response => {
    // 统一处理业务逻辑
    if (response.data.code === 401) {
        // token 过期，跳转到登录页
        router.push('/login');
    }
    return response;
}, error => {
    return Promise.reject(error);
});
```

**本项目用途：** 自动在所有请求中带上 JWT 令牌，自动处理 401 未登录情况。

# 十二、RESTful API

---

### 12.1 ⭐⭐⭐ 什么是 RESTful API？

**八股文答案：**
RESTful API 是**一种 API 设计规范**，用 URL 表示资源，用 HTTP 方法表示操作。

**核心原则：**
- 用名词表示资源（如 `/users` 表示用户资源）
- 用 HTTP 方法表示操作：
  - `GET /users` → 获取用户列表
  - `GET /users/1` → 获取 ID=1 的用户
  - `POST /users` → 新增用户
  - `PUT /users/1` → 修改 ID=1 的用户
  - `DELETE /users/1` → 删除 ID=1 的用户
- 无状态：每次请求独立，服务器不存客户端状态
- 统一接口：返回 JSON 格式数据

**反例（不是 RESTful）：**
```
GET /getUserList
POST /addUser
POST /deleteUser?id=1
```
**正例（RESTful）：**
```
GET /api/user/list
POST /api/user
DELETE /api/user/1
```

---

### 12.2 ⭐⭐ HTTP 状态码含义？

**八股文答案：**
| 状态码 | 含义 | 场景 |
|--------|------|------|
| 200 | OK 成功 | 查询成功 |
| 201 | Created 已创建 | 新增成功 |
| 400 | Bad Request 请求错误 | 参数不合法 |
| 401 | Unauthorized 未认证 | 没有登录或令牌过期 |
| 403 | Forbidden 无权限 | 登录了但没有权限 |
| 404 | Not Found 未找到 | 接口不存在 |
| 500 | Internal Server Error 服务器错误 | 后端代码报错 |

### 13.2 ⭐⭐ 项目部署常用命令？

**八股文答案：**
```bash
# 1. 打包
mvn clean package -DskipTests

# 2. 上传到服务器（scp 或 ftp）
scp target/szybegin.jar root@服务器IP:/app/

# 3. SSH 登录服务器
ssh root@服务器IP

# 4. 启动项目（后台运行）
nohup java -jar /app/szybegin.jar > /app/log.log 2>&1 &

# 5. 查看是否启动成功
ps -ef | grep java
tail -f /app/log.log

# 6. 停止项目
kill -9 进程ID

# 7. 前端部署
npm run build
# 把 dist/ 目录上传到服务器 Nginx 的 html 目录
```

**nohup 解释：** 即使关闭 SSH 连接，程序继续在后台运行。
`>` 是重定向输出到日志文件，`2>&1` 把错误输出也重定向到日志文件，最后的 `&` 表示后台运行。

# 十四、常见场景题

---

### 14.1 ⭐⭐⭐ 浏览器输入 URL 到页面显示，发生了什么？

**八股文答案：**
1. **DNS 解析**：把域名（如 www.baidu.com）解析成 IP 地址
2. **TCP 连接**：与服务器建立三次握手连接
3. **发送 HTTP 请求**：浏览器向服务器发请求（GET /index.html）
4. **服务器处理请求**：
   - Nginx 收到请求，如果是静态资源直接返回，如果是 API 转发到后端
   - 后端经过 Security 过滤器链 → Controller → Service → Mapper → 数据库
   - 返回 JSON 或 HTML
5. **浏览器解析渲染**：
   - 解析 HTML → DOM 树
   - 解析 CSS → CSSOM 树
   - 合并成渲染树
   - 布局（Layout）→ 绘制（Paint）
6. **Vue 项目特殊处理**：加载到 JS 后，Vue 接管页面，创建 Vue 实例，渲染组件

---

### 14.2 ⭐⭐ 从输入 URL 到登录完成，完整流程？

**八股文答案：**
1. 浏览器输入 `http://localhost:8080`
2. Nginx 返回 index.html（Vue 打包后的文件）
3. 浏览器加载 JS，Vue 启动
4. 前端路由守卫检查 token → 没有 token → 跳转到 `/login`
5. 用户在登录页输入用户名密码，点击登录
6. 前端发 POST 请求到 `/api/login`
7. 后端 Spring Security 验证用户名密码
8. 验证通过，生成 JWT 令牌，返回给前端
9. 前端存到 localStorage
10. 跳转到首页，发请求时自动带 token

# 十五、开放性加分题

---

### 15.1 ⭐⭐ 你们项目是怎么处理异常的？

**答：** 用了一个全局异常处理器 `@ControllerAdvice` + `@ExceptionHandler`。不管哪个 Controller 报错，都会统一到这里处理，返回统一格式 `{code: 500, message: "错误信息"}`。这样前端统一处理错误，不用每个接口单独写 try-catch。

---

### 15.2 ⭐⭐ 你怎么理解"高内聚低耦合"？

**答：** 
- **高内聚**：把相关的功能放在一起。比如用户相关的所有操作（登录、注册、修改信息）都在 UserService 里
- **低耦合**：模块之间依赖尽量少。Controller 只依赖 Service 接口（不依赖实现），Service 只依赖 Mapper 接口

本项目四层架构（Controller → Service → Mapper → DB）就是高内聚低耦合的典型例子。

---

### 15.3 ⭐⭐ 什么是设计模式？你在项目中用过哪些？

**答：** 设计模式是解决常见编程问题的"标准答案"。

本项目用到的：
| 模式 | 项目中哪里用到了 |
|------|----------------|
| **单例模式** | Spring Bean 默认就是单例（@Service、@Controller 等）|
| **工厂模式** | Spring IOC 容器本身就是工厂 |
| **代理模式** | AOP 就是基于代理实现的 |
| **模板方法模式** | Service 接口定义模板，Impl 实现具体逻辑 |
| **适配器模式** | 数据同步时把采集格式转为业务格式 |

---

### 15.4 ⭐⭐ 如果前端传过来的日期格式不对，你怎么处理？

**答：** 两种处理方式：
1. **统一配置日期格式化**（推荐）：在 Spring Boot 配置中指定日期格式，全局生效
2. **在实体类上用 @JsonFormat 注解**：
```java
@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
private Date createTime;
```

---

### 15.5 ⭐⭐ 一个表有1000万条数据，查询很慢怎么办？

**答：** 分步排查和处理：
1. **先看慢查询日志**：找到最慢的 SQL
2. **加索引**：对 WHERE 条件中的字段、ORDER BY 的字段加索引
3. **分页优化**：不要用 `LIMIT 100000, 10`（越往后越慢），用"延迟关联"优化
4. **数据归档**：旧数据（如一年前的）移到历史表
5. **读写分离**：主库写，从库读
6. **引入缓存**：热点数据放 Redis
