### Q1：简单介绍一下你这个项目

**答：** 这是一个**水资源监测管理系统**，是给鄂北地区的供水工程用的。简单说就是：在河道、水库、水厂装了各种传感器设备（测水位、测流量、测水质），这些设备每5分钟采集一次数据。我的系统负责：
1. 把设备采集的数据自动同步到数据库
2. 在网页上展示实时数据（水位多高、流量多大、水质好不好）
3. 设备出故障了自动报警
4. 管理人员可以在网页上看地图、看图表、管理用户权限

总之就是一个**"水情数据大屏 + 设备监控 + 后台管理"**的综合系统。

### Q2：这个项目用了什么技术栈？

**答：** 后端用 **Java 8 + Spring Boot 2.6.2 + MyBatis-Plus + MySQL + Redis**。前端用 **Vue 2 + Element UI + Axios**。数据库有5个（分库存储不同业务数据）。登录认证用 **Spring Security + JWT**。文件存阿里云OSS，短信用腾讯云。图表用ECharts，地图用Leaflet和高德地图。

### Q5：说说这个项目的用户角色和权限体系？

**答：** 项目用了**RBAC（基于角色的权限控制）**模型。简单说就是：用户 → 角色 → 权限。一个用户可以有多个角色，一个角色有多个权限。比如"管理员"角色有全部权限，"巡检员"角色只能看巡检相关的页面。前端根据权限动态显示菜单，后端用 Spring Security 的 `@PreAuthorize` 注解在接口上做权限校验。

### Q6：描述一下用户登录的完整流程？

**答：** ① 用户在浏览器输入用户名密码 → ② 前端发 POST 请求到 `/login` → ③ 后端 Security 框架验证用户名密码 → ④ 验证通过后，后端生成一个 JWT 令牌（包含用户ID、过期时间等信息，用密钥签名）→ ⑤ 把令牌返回给前端 → ⑥ 前端把令牌存到 localStorage → ⑦ 之后每次请求，前端在 Header 里带上 `Authorization: Bearer xxxxx` → ⑧ 后端的 JWT 过滤器解析令牌，知道是谁在请求 → ⑨ 令牌过期（7天），用户重新登录。

---

### Q7：什么是 JWT？为什么要用它？

**答：** JWT 就是"JSON Web Token"，一个加密的字符串，里面包含用户信息。为什么用它？因为传统的 Session 方式需要在服务器内存里存登录状态，用户多了占内存，而且多台服务器不好共享。JWT 是无状态的——用户拿着令牌来，我一解密就知道是谁，不需要在服务器存任何东西。本项目 JWT 的有效期是7天。

### Q31：Spring Boot 和 Spring 有什么区别？

**答：** Spring 是一个老牌的 Java 框架，功能强大但配置繁琐（要写很多 XML 配置文件）。Spring Boot 在 Spring 基础上做了"自动配置"——它预置了大量默认配置，你基本不用配什么就能直接运行。类比：Spring 是买了一套精装修的毛坯房（得自己装灯、装马桶），Spring Boot 是拎包入住的酒店（啥都准备好了）。本项目用的 Spring Boot 2.6.2。

---

### Q32：@SpringBootApplication 这个注解是什么作用？

**答：** 它是一个**组合注解**，相当于三个注解合在一起：
1. `@Configuration` — 标记这个类是配置类
2. `@EnableAutoConfiguration` — 启动自动配置（Spring Boot 的核心）
3. `@ComponentScan` — 自动扫描当前包及其子包下的所有组件（Controller、Service 等）

所以启动类只要加了 `@SpringBootApplication`，Spring Boot 就能自动找到所有代码并启动。

---

### Q33：MyBatis-Plus 和 MyBatis 有什么区别？

**答：** MyBatis 需要你自己写 SQL（在 XML 文件里写 SELECT/INSERT/UPDATE/DELETE）。MyBatis-Plus 是 MyBatis 的增强版——它帮你把常用的 SQL 都自动生成了。你只需要让你的 Mapper 接口继承 `BaseMapper<T>`，就有了 `selectById`、`selectList`、`insert`、`updateById`、`deleteById` 等方法，不用写一行 SQL。只有复杂查询才需要手写 SQL。本项目大部分操作都不用手写 SQL。

---

### Q34：BaseMapper 里有哪些常用方法？

**答：**
```java
selectById(id)              // 根据主键查一条
selectList(wrapper)         // 查列表（带条件）
selectOne(wrapper)          // 查一条（带条件）
selectPage(page, wrapper)   // 分页查询
insert(entity)              // 新增
updateById(entity)          // 根据主键修改
update(entity, wrapper)     // 按条件修改
deleteById(id)              // 根据主键删除
delete(wrapper)             // 按条件删除
selectCount(wrapper)        // 统计数量
```

---

### Q35：QueryWrapper 是什么？怎么用的？

**答：** QueryWrapper 是 MyBatis-Plus 的**条件构造器**，用来拼接 SQL 的 WHERE 条件。比如你想查"状态为1且名字里带'张'的用户，按创建时间倒序"，用 Java 代码写：
```java
QueryWrapper<User> wrapper = new QueryWrapper<>();
wrapper.eq("status", 1)            // WHERE status = 1
       .like("username", "张")     // AND username LIKE '%张%'
       .orderByDesc("create_time"); // ORDER BY create_time DESC
List<User> list = userMapper.selectList(wrapper);
```
这样就不用写 SQL 了，MyBatis-Plus 会自动生成。

---

### Q36：项目中的分页查询是怎么实现的？

**答：** 分三步：
1. **配置分页插件**：在 MybatisPlusConfig 中注册了 `PaginationInnerInterceptor`
2. **Service 层调用**：`Page<Entity> page = new Page<>(pageNum, pageSize)`，传给 Mapper
3. **Mapper 查询**：`mapper.selectPage(page, wrapper)`，返回结果中包含了 `records`（当前页数据）、`total`（总条数）、`pages`（总页数）

前端拿到数据后，用 Element UI 的 `<el-pagination>` 组件展示分页按钮。

### Q37：本项目怎么切换数据库的？@DS 注解怎么用？

**答：** 项目有5个数据库，用 `@DS` 注解切换。默认操作 gcdd 库，如果想操作其他库：
```java
@Service
@DS("jcxx")  // 整个 Service 都操作 jcxx 库
public class DeptServiceImpl implements DeptService { }

// 或者只在方法上切换
@Override
@DS("collector")
public List<CollectorData> getData() {
    return mapper.selectList(null);
}
```
这是通过 Baomidou 的 `dynamic-datasource` 框架实现的。

### Q38：跨域问题是什么？本项目怎么解决的？

**答：** 跨域就是：前端在 `localhost:8080` 运行，后端在 `localhost:8081`，浏览器认为这是两个不同的"源"，默认禁止它们通信。本项目在 `CorsConfig.java` 中配置了跨域过滤器，允许所有来源（`allowedOrigins("*")`）、所有方法（`allowedMethods("*")`）的请求。这样前端就能正常调用后端接口了。

---

### Q39：前端怎么拿到 JWT 令牌的？存在哪里？

**答：** 用户登录成功后，后端的 `LoginSuccessHandler` 把 JWT 令牌放在响应头 `Authorization` 字段返回。前端拿到后存到浏览器的 `localStorage`（本地存储）里。之后每次发请求，Axios 的请求拦截器从 localStorage 取出 token，放在请求头的 `Authorization: Bearer xxx` 里带给后端。

---

### Q40：密码存在数据库里是明文吗？

**答：** 不是。密码用 **BCryptPasswordEncoder** 加密后存储。BCrypt 是一种哈希算法，特点是：每次加密结果都不一样（加了随机盐），而且计算速度慢（防止暴力破解）。用户登录时，把用户输入的密码和数据库里加密后的密码做比对，匹配就通过。即使数据库泄露，攻击者也拿不到原始密码。

---

### Q41：项目中的定时任务是怎么实现的？

**答：** 用 Spring 自带的 `@Scheduled` 注解。在 `SzyApplication` 启动类上加了 `@EnableScheduling` 开启定时任务功能。然后在 `DataSyncTask` 类的多个方法上加 `@Scheduled(cron = "0 0/5 * * * ?")`，意思是"每5分钟执行一次"。这个任务做三件事：
1. 同步水质数据
2. 同步流量数据
3. 同步水位数据
4. 检查设备状态（离线检测、数据异常检测）

### Q42：设备故障是怎么自动检测的？

**答：** 在 `DataSyncTask.monitorDeviceStatus()` 方法中，每5分钟检查一次。**检测两种故障：**
1. **离线故障（offline）**：设备的 `ONLINE` 字段为 "0"（主动离线），或最后通讯时间超过24小时（通讯超时）
2. **数据异常（no_data）**：设备在线，但所有采集表中都没有这个设备的最新数据（近2小时内）

发现故障就插入一条记录到 `device_fault_history` 表，状态为 `active`（活跃）。设备恢复正常后，自动把故障状态改为 `resolved`（已解决），并记录恢复时间。

---

### Q43：设备从故障状态自动恢复的逻辑是什么？

**答：** 每5分钟巡检时，对**当前有活跃故障**的设备做检查：
- **离线故障恢复**：如果这个设备有"离线"类型的活跃故障，但现在通讯恢复并且ONLINE=1 → 把故障状态改成 `resolved`，记录当前时间为恢复时间
- **数据异常恢复**：如果这个设备有"no_data"类型的活跃故障，但现在采集表中有新数据了 → 同样改为 `resolved`

简单说就是：每次巡检都是"发现问题就新增故障记录，发现恢复就关闭故障记录"。

### Q71：这个项目最大的难点是什么？

**答：** 我遇到的主要难点有三个：
1. **多数据源管理**：5个数据库之间的数据同步。特别是 collector 库的采集数据需要每5分钟同步到业务库，要保证数据不丢失、不重复。
2. **设备故障自动检测与恢复**：几十上百台设备，要准确判断每台设备的状态（在线但无数据、离线、通讯超时），不能误报也不能漏报。

### Q72：数据同步怎么保证不丢数据？

**答：** 目前的策略是**每5分钟全量同步**。具体做法：读取 collector 库里自上次同步之后的新数据，插入到业务库。虽然不够实时（最多5分钟延迟），但对于水资源监测来说够了。如果要更可靠，可以加：
1. **断点续传**：记录上次同步到的数据ID或时间戳，下次从断点开始
2. **幂等性**：相同的同步操作执行多次结果一样（如果数据已存在就跳过）
3. **同步日志**：记录每次同步了多少条数据，方便排查

### Q73：如果采集器数据量大增（比如从100台设备加到10000台），系统会有什么问题？怎么优化？

**答：** 可能的问题：
1. **定时任务执行超时**：每5分钟同步一次，但数据量太大5分钟跑不完
2. **数据库查询变慢**：采集表数据量上亿条后，查询会很慢
3. **前端图表加载慢**：数据量大了，ECharts 渲染会卡

优化方案：
1. **分库分表**：按设备ID或时间分表，比如一个月一张表
2. **数据归档**：旧数据（比如1个月前的）归档到历史库
3. **引入消息队列**：用 RabbitMQ 或 Kafka，采集数据先入队列，异步写入业务库
4. **索引优化**：对常用查询字段（设备编码、时间）加索引
5. **数据聚合**：图表展示时不做实时查询，而是查预先聚合好的统计数据

### Q74：JWT 令牌被偷了怎么办？

**答：** JWT 是无状态的，服务器没有记录哪些令牌有效，所以被偷了没法主动让它失效。解决方案：
1. **设置短过期时间**：本项目是7天，可以缩短到1天或几小时
2. **结合 Redis 黑名单**：用户修改密码或退出登录时，把令牌加入 Redis 黑名单
3. **刷新令牌机制**：用 refresh token + access token 双令牌，access token 短时间（15分钟）过期，refresh token 长时间有效（7天）。access token 被偷了影响范围小
4. **HTTPS**：全站 HTTPS 传输，防止令牌被中间人截获

### Q75：为什么要把数据存在5个数据库而不是1个？

**答：** 好处：
1. **职责分离**：采集数据量大、写入频繁，放在独立库里不影响业务库的查询性能
2. **权限控制**：不同部门可能只管理部分数据，分库后可以单独控制访问
3. **维护方便**：可以单独备份某个库、优化某个库的性能

坏处：
1. **跨库查询麻烦**：不能直接 JOIN 查询，需要在代码里做多次查询再组合
2. **事务管理复杂**：一个操作涉及多个库时，没法用数据库事务保证一致性

### Q76：这个项目有性能瓶颈吗？怎么发现的？

**答：** 可能的性能瓶颈：
1. **定时任务同步数据**：每5分钟全量查采集表，设备多了采集表数据量巨大，可能超时
2. **Excel 导出**：如果一次性导出几万条数据，内存可能爆掉
3. **地图加载**：几百个标记同时显示，前端会卡

发现方式：看日志（有没有执行超时的警告）、问实际使用者（哪个页面打开慢）、用压测工具（JMeter 模拟多人同时访问）。

### Q77：如果让你重构这个项目，你会怎么改进？

**答：** 如果要改进，我会做这几件事：
1. **引入消息队列（RabbitMQ）**：采集数据先入队列，异步处理，削峰填谷
2. **前后端分离更彻底**：目前 Vue 2 + Webpack 3 较老，可以升级到 Vue 3 + Vite
3. **缓存层加强**：更多静态数据用 Redis 缓存，减少数据库压力
4. **引入操作日志**：用 AOP 记录每个用户的操作日志，方便审计
5. **代码生成器规范化**：MyBatis-Plus 有代码生成器，统一代码风格

### Q78：这个项目怎么保证安全性？

**答：** 安全性措施：
1. **密码加密**：BCrypt 加密，不是明文存储
2. **JWT 认证**：每次请求都需要验证令牌
3. **权限控制**：不同用户只能访问有权限的接口
4. **防 SQL 注入**：MyBatis-Plus 用参数预编译，不是拼接 SQL
5. **防全表更新**：MybatisPlusConfig 配置了 BlockAttackInnerInterceptor，防止误操作导致全表更新
6. **CORS 配置**：虽然目前是允许所有来源，生产环境可以限制指定域名

### Q79：前端页面加载慢怎么排查？

**答：** 排查步骤：
1. **打开浏览器 F12 → Network**：看哪个接口请求时间长 → 优化后端查询
2. **看资源大小**：JS 文件/CSS 文件是不是太大了 → 开启 Gzip 压缩
3. **看请求数量**：一个页面是不是发了太多请求 → 合并请求
4. **看渲染性能**：是不是有大量 DOM 操作 → 虚拟列表优化

本项目前端 Webpack 3 打包可能比较大，可以用 webpack-bundle-analyzer 分析哪些模块占体积大。

### Q80：项目中的 ECharts 图表数据量太大导致卡顿怎么办？

**答：** 几种优化方法：
1. **数据采样**：如果1万条数据，隔几条取一条，减少到几百条
2. **开启 ECharts 渐进式渲染**：配置 `progressive: 200`，分块渲染
3. **使用 WebWorker**：数据计算放在后台线程，不阻塞 UI
4. **异步加载**：先显示大概趋势，用户放大后再加载详细信息
5. **后端聚合**：不返回原始数据，而是返回按小时/天统计后的值

### Q81：如果设备上报的数据格式变了，你的系统怎么适配？

**答：** 加一个**适配层**（Adapter模式）。在数据同步时，用一个转换器把采集表数据转成业务表数据。如果采集器换了厂家、数据格式变了，只需要改这个转换器的逻辑，不影响其他代码。目前 DataSyncTask 里同步数据时应该已经做了类似的处理（把采集器的原始数据单位、格式转换为业务系统的标准格式）。

### Q82：说一个你解决过的 Bug？

**答：** （准备一个真实的，没有就说下面的）比如：设备离线故障重复上报的问题。原来的逻辑是每次巡检发现设备离线就新增一条故障记录。但如果设备一直离线，每5分钟就新增一条，数据库里全是重复记录。修复方案：查询故障表里该设备有没有"活跃中"的离线故障，如果有就不重复新增。只有**状态变化时**（在线→离线，或离线→在线）才记录。这个逻辑现在已经在 DataSyncTask 里实现了。

### Q83：项目中的 @Transactional 事务注解用在哪儿？

**答：** Spring Boot 启动类上已经加了 `@EnableTransactionManagement` 开启事务管理。`@Transactional` 可以加在 Service 方法上，作用是：这个方法里的多个数据库操作**要么全部成功，要么全部回滚**。比如转账操作：扣钱 + 加钱两个操作，任何一个失败，两个都撤销。本项目在需要保证数据一致性的地方会用到。

### Q84：如果让你给这个项目加一个新功能——操作日志，你怎么设计？

**答：** 用 **AOP（面向切面编程）** 实现：
1. 建一个操作日志表：`oper_log`（id、操作人、操作类型、操作内容、IP地址、操作时间）
2. 自定义一个注解 `@Log("删除用户")`
3. 用 AOP 拦截加了 `@Log` 注解的方法，自动记录操作详情
4. 在需要记录日志的 Controller 方法上加上 `@Log("xxx")` 就行

优点是不用改业务代码，一个注解就搞定。

### Q85：怎么防止用户未登录就直接在浏览器输入 URL 访问后台页面？

**答：** 前端和后端双重保障：
1. **前端路由守卫（路由拦截器）**：在 Vue Router 里配置，跳转前检查 localStorage 有没有 token，没有就强制跳到登录页
2. **后端权限拦截**：所有非白名单的接口都需要 JWT 认证，没有 token 返回 401
3. **前端菜单动态生成**：未登录不显示菜单，只显示登录页

---

### Q86：项目中的"防全表更新"是什么？

**答：** MybatisPlusConfig 中配置了 `BlockAttackInnerInterceptor`，这个拦截器的作用是：如果你调用 `update` 或 `delete` 方法时**没有传条件**（wrapper 为空），它会直接报错阻止操作。比如：
```java
// 本来想删除 status=0 的用户
userMapper.delete(null);  // 忘记了条件！
// 有拦截器 → 报错！不会真的删掉全表数据
```
这是防止"手滑"的保险。

### Q87：前端打包后文件太大怎么优化？

**答：** 本项目 Webpack 3 打包体积优化方案：
1. **路由懒加载**：按页面拆分 JS，访问哪个页面加载哪个
2. **CDN 引入**：把 Vue、Element UI、ECharts 等大库用 CDN 引入，不打入打包文件
3. **开启 Gzip**：Nginx 配置 Gzip 压缩，文件能减少 60-70%
4. **图片压缩**：用 webp 格式或 tinypng 压缩
5. **去除 console.log**：生产环境不打印调试日志

### Q88：说说你对前后端分离的理解？

**答：** 前后端分离就是：**前端和后端是两个独立的项目**。
- **前端**：负责页面展示和交互（HTML/CSS/JS），运行在浏览器
- **后端**：负责业务逻辑和数据存储（Java），运行在服务器

**好处**：
1. 前端和后端可以同时开发，互不等待
2. 分工明确，前端不用管数据库，后端不用管页面样式
3. 一套后端可以给多个前端用（网页端、手机端、小程序）

**坏处**：
1. 需要联调（前后端对接口格式）
2. 跨域问题
3. 对 SEO 不友好（但本项目是后台管理系统，不需要 SEO）

### Q89：MyBatis-Plus 代码生成器是什么？

**答：** 项目中有个 `CodeGenerator.java`，就是 MyBatis-Plus 的代码生成器。它的作用是：**根据数据库表结构，自动生成对应的 Java 代码**。包括：
- Entity 类（对应表结构）
- Mapper 接口
- Service 接口和实现类
- Controller
- Mapper XML 文件

如果有100张表，手动写代码要写一周，生成器几分钟就搞定了。

### Q90：项目中用的 Leaflet 和 OpenLayers 有什么区别？为什么同时用两个？

**答：** 
- **Leaflet**：轻量（40KB），简单易用，适合标注位置、弹出详情。API 友好，学习成本低
- **OpenLayers**：重量级，功能强大，支持复杂 GIS 操作（坐标系转换、地图投影、WMS 服务等）

同时用两个可能是因为：简单的地图展示用 Leaflet，需要复杂 GIS 分析的时候用 OpenLayers。或者只是不同的开发者用了不同的库，没有统一。

### Q91：如果 Redis 挂了会怎么样？

**答：** 本项目用 Redis 做缓存，Redis 挂了的影响：
1. **缓存失效**：所有请求直接打到数据库，数据库压力增大
2. **系统降级**：如果数据库扛不住，页面会变慢甚至超时
3. **不会丢核心数据**：因为核心数据在 MySQL 里，Redis 只是缓存，丢了可以从 MySQL 重新加载

优化方案：配置 Redis 主从或哨兵模式实现高可用。代码层面加降级逻辑：Redis 挂了就跳过缓存，直接查数据库。

### Q92：项目的日志配置在哪里？怎么查看？

**答：** Spring Boot 默认用 Logback 作为日志框架。日志配置可能在 `application.yml` 里或单独 `logback-spring.xml` 文件。日志会输出到：
1. **控制台**（开发时看）
2. **日志文件**（部署后看，一般在 `logs/` 目录下）

可以用 `@Slf4j` + `log.info()` / `log.warn()` / `log.error()` 在不同级别打印日志。

### Q93：怎么保证定时任务在集群部署时不会重复执行？

**答：** 如果项目部署了多台服务器，每台都会执行定时任务，导致数据同步多次。解决方案（目前项目没有做）：
1. **分布式锁（Redis）**：执行任务前先抢锁，抢到的执行，抢不到的跳过
2. **@SchedulerLock**：一个专门解决这个问题的库
3. **任务调度中心**：用 XXL-JOB 等专业调度框架，统一管理任务

### Q94：说说你对微服务的理解，本项目为什么没拆分微服务？

**答：** 微服务就是把一个大项目拆成多个小项目独立部署。比如本项目可以拆成：用户服务、数据采集服务、预警服务、监控服务。

本项目是**单体应用**（一个项目包含所有功能）。单体应用的优点：
1. 架构简单，开发和部署方便
2. 适合团队规模小、业务不太复杂的场景
3. 没有分布式带来的复杂度（网络延迟、数据一致性等）

本项目目前是单体就够了。如果以后用户量大、团队扩充、需要独立部署某个模块，可以考虑拆分。

### Q97：Vue 中 v-if 和 v-show 有什么区别？

**答：**
- **v-if**：条件为 false 时，直接**不渲染**这个元素（DOM 中没有这个节点）。适合切换频率低的场景
- **v-show**：条件为 false 时，给元素加 `display: none`（隐藏但 DOM 中还存在）。适合频繁切换的场景

性能上：v-if 有更高的切换开销（要创建/销毁 DOM），v-show 有更高的初始渲染开销（不管显不显示都先渲染）。

## 面试技巧总结

### 回答问题的"STAR"原则
- **S**ituation（背景）— 这个功能是解决什么问题的
- **T**ask（任务）— 需要做什么
- **A**ction（行动）— 你怎么做的
- **R**esult（结果）— 效果怎么样

### 不会的问题怎么答
- "这个问题我还没有深入研究，但我的理解是..."
- "我不确定这个细节，但如果是我的话我会这样实现..."

### 不要说的
- "这个不是我负责的"（显得你参与度不高）
- "这很简单"（显得你不谦虚）
- 背概念但说不清项目里的实际用法（面试官一听就是背的）
